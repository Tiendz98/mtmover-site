How a tenant-to-tenant migration works

1. Connect both tenants

Tenants are connected through admin consent. For email, access can be limited to chosen mailboxes with Exchange RBAC for Applications.

2. Map source to target

Auto-map matches users and sites, adjust by hand, and export or import every mapping as CSV.

3. Check each pair

Only pairs that passed Check move on to the Migrate step.

4. Dry-run, then migrate

Dry-run is on by default, so you see what would be copied before anything is written.

5. Review and re-run

Pair status survives a restart, and each pair has a detail window of what was migrated. Re-run to pick up only new items.

Source stays untouched

MTMover only copies. It never edits the source tenant.

Questions about tenant migration with MTMover

Does it change my source tenant?

No. Source access is read-only and MTMover only copies data.

Where does it run?

On your own Windows PC. Nothing to host and no service to rent.

Can I try it first?

Yes. The free trial lasts 14 days with 5 items per module run, and no credit card is needed.

Can I limit which mailboxes it can access?

Yes. For email, access can be limited to chosen mailboxes with Exchange RBAC for Applications.

Can I sync again before cutover?

Yes. Delta re-runs skip items that were already migrated.
